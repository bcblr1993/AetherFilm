# Canonical EOF playback fixtures

These assets are generated by AetherNative from FFmpeg's `testsrc2` video and a
440 Hz sine wave. They contain no external media and are covered by the
repository's [MIT license](../../LICENSE).

The EOF and blocked-seek tests qualify actual unread packet ranges. Preserve
these exact bytes across machines: newer encoder versions can change MP4
packet positions even with the same generation command. The fixture generator
checks both SHA-256 values, copies the pair into a fresh output directory, and
uses `ffprobe` to verify packet bounds, the final video frame and the held audio
tail. Other playback fixtures are still generated normally.

| Asset | Bytes | SHA-256 |
| --- | ---: | --- |
| `clip-short-gop.mp4` | 796257 | `33e46b39e57f4e6cd56713f013dc573df8cd3b0d9debda10c4bf2a445c16bd75` |
| `clip-short-gop-tail.json` | 195 | `f3a569fe0218d3d1d80a7f1a12deb46d7e80eb2019fbf5e8e3e1005950110f13` |
| `clip-tail-long-gop.mp4` | 747808 | `41ba7c5011ee990d43e079d687533d2f01f276112dd9002e8b53346792af858b` |

The dedicated long-GOP tail control has only the keyframe at zero, a final video
PTS of 11.933333 and packet end at 12 seconds. Its generator also verifies
packet bounds and this layout. It was generated by the same command below
without the GOP/keyframe options. The ordinary `clip-h264.mp4` and other original
container/SMB fixtures continue to be generated normally; their bytes are not
silently substituted by the new control.

Original synthetic video generation command:

```sh
ffmpeg -hide_banner -loglevel error -nostdin \
  -f lavfi -i testsrc2=size=320x180:rate=15 \
  -f lavfi -i sine=frequency=440:sample_rate=48000 \
  -t 12 -c:v libx264 -preset ultrafast \
  -pix_fmt yuv420p -g 15 -keyint_min 15 \
  -x264-params keyint=15:min-keyint=15:scenecut=0 \
  -c:a aac -b:a 64k -movflags +faststart clip-short-gop.mp4
```

The companion JSON records the actual packet layout measured with `ffprobe`:
the 391-byte audio tail begins at byte 795866, after the final video PTS
11.933333. The blocked-seek qualification uses the keyframes at 4 seconds
(byte 267381) and 8 seconds (bytes 539857–548852, upper bound exclusive 548853).
Re-encoding requires a separately reviewed fixture and range qualification; it
does not replace these canonical assets automatically.

Generate the complete fixture set from the repository root as before:

```sh
python3 PlaybackTests/generate_fixtures.py --output /path/to/fresh-fixtures
```

These files are test inputs and are not included in the Xcode app resources.
